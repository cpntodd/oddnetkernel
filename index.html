oddnetkernel

Oddsoul's custom Linux kernel — tuned to squeeze maximum performance from AMD Zen/Polaris hardware on Debian. Built with Clang 21 and Zen-kernel interactive patches.

Install Features Tuning Build GitHub

Install

One command. Debian 13 (Trixie), amd64.

$ curl -s 'https://raw.githubusercontent.com/cpntodd/oddnetkernel/master/install-oddnetkernel.sh' | sudo bash

Adds the oddnetkernel apt repo, installs the kernel + headers, and updates GRUB.

Manual Install

# Add the GPG key
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://cpntodd.github.io/oddnetkernel/oddnetkernel-archive-keyring.gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/oddnetkernel-archive-keyring.gpg

# Add the apt source
echo 'deb [arch=amd64 signed-by=/etc/apt/keyrings/oddnetkernel-archive-keyring.gpg] https://cpntodd.github.io/oddnetkernel/repo stable main' | \
    sudo tee /etc/apt/sources.list.d/oddnetkernel.list

# Install
sudo apt update
sudo apt install 'linux-image-*-oddnetkernel-zen' 'linux-headers-*-oddnetkernel-zen'
sudo reboot

Features

🧠 Zen Interactive Tuning

Zen-kernel patchset tunes for desktop responsiveness — process scheduling, memory reclaim, I/O, and CPU frequency scaling all favour low-latency interactivity over throughput.

🎯 AMD Zen+ / Polaris

Built on and for Ryzen 5 2600 (Zen+) and Radeon RX 570/580 (Polaris). Full amdgpu with SI/CIK and Display Core enabled.

🔧 Clang 21 + LLD

Compiled with LLVM/Clang 21.1.8 and LLD 21 — a thinner, modern toolchain producing a fast-linking kernel.

📦 Broad Hardware Support

  • CIFS/SMB, Btrfs, XFS, NTFS3, exFAT, OverlayFS
  • NFS client & server
  • WireGuard, Bridge, VXLAN
  • KVM, VIRTIO, NVMe
  • Realtek r8169 (built-in)

Performance Tuning

Setting Value
CPU Scheduler EEVDF — Earliest Eligible Virtual Deadline First
Preemption PREEMPT_DYNAMIC — lazy preemption for desktop
Timer tick 1000 Hz — low-jitter scheduling
I/O Scheduler mq-deadline — multiqueue-aware
TCP Congestion CUBIC
RCU Preemptible tree-based hierarchical RCU

Zen-kernel interactive tuning adjusts: block layer (I/O scheduler selection), virtual memory (watermark boost, hugepage reclaim), CPUFreq governor thresholds, and split-lock detection — all biased toward desktop responsiveness.
